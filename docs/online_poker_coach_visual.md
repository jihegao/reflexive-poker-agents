# 在线多人扑克“牌局教练”视觉方案

![桌面端概念图](assets/online-poker-coach-concept.png)

## 1. 使用场景与产品边界

这是一个“人做决定、系统给建议”的旁路教练台，面向：

- 自建或明确允许辅助工具的多人牌局；
- 训练、复盘、教学和观战；
- 本仓库仿真环境的实时可视化。

不做自动下注、自动点击、隐藏信息读取或规避平台检测。第三方牌局接入前必须确认平台规则；不允许实时辅助的平台只提供延迟复盘模式。

## 2. 核心体验

每个决策点都要让玩家在 1 秒内回答四个问题：

1. 现在轮到谁、底池和下注是多少？
2. 建议动作是什么，下注尺度是多少？
3. 为什么这样做，模型有多确定？
4. 数据是否仍然新鲜，还是已经过期？

视觉优先级依次为：**牌桌状态 → 主建议 → 合法操作 → 依据与对手模型 → 历史解释**。

## 3. 页面布局

### A. 顶部状态栏（56 px）

- 产品名“牌局教练”；
- Hand 编号、盲注、前注和模式；
- 连接状态、事件延迟、建议生成耗时；
- 固定显示“训练模式 / 允许辅助 / 延迟复盘”标签，避免误用。

### B. 牌桌区（约 68% 宽度）

- 16:9 桌面端以六人桌为基准，英雄位固定在下方；
- 玩家卡片只显示头像、位置、筹码和当前动作；
- 公共牌、底池和当街下注保持中心对齐；
- 正在行动者使用青色轮廓，已弃牌者降至 35% 明度；
- 不可见手牌始终背面显示，防止 UI 暗示系统掌握隐藏信息。

### C. 实时建议轨（约 32% 宽度）

首屏只保留一张主建议卡：

- `建议：加注至 6.5 BB`；
- 胜率、置信度和数据时间戳；
- Fold / Call / Raise 的策略混合；
- 两条可审计依据，例如“底池赔率 28%”“对手弃牌偏高”；
- 对手倾向摘要与样本量，低样本时显示“证据不足”。

“为什么”默认只展示简短依据，不展示或索取隐藏推理过程。展开区可显示风险、假设、下一街计划和反事实比较。

### D. 底部操作坞（154 px）

- Fold、Check/Call、Raise 三个合法动作；
- 按钮展示实际代价或目标总额，例如 `Call 1.5 BB`、`Raise to 6.5 BB`；
- 建议动作获得强调，但三者都保持可点击；
- 只记录玩家选择，不向外部牌局自动发出动作；
- 倒计时最后 5 秒转为琥珀色，不使用惊吓式红色闪烁。

Hero 由 LLM 接管时，动作按钮替换为 `收回控制`、`暂停` 和 `单步`，同时在 Hero 座位卡显示 `LLM 已接管 · S3`。玩家收回控制后恢复合法动作按钮；切换不改变 Hero 的筹码、公开形象、对手统计或策略历史。

### E. 策略版本面板

- 只服务于 Hero 的 `closed-loop-shaper`，不允许改写对手策略；
- 展示当前策略版本、结构化参数、最近 patch 和应用原因；
- 以字段级 diff 表达 `S2 → S3`，而不是只显示一段模型文本；
- 玩家和绑定到 Hero 的 LLM 都能提交受限 patch；
- 提供回滚入口，并明确标注 patch 的 proposed、applied、rejected、rolled back 状态；
- 不提供源代码、提示模板、工具权限或任意 JSON 编辑入口。

## 4. 状态与反馈

| 状态 | 牌桌表现 | 建议区表现 | 操作区表现 |
|---|---|---|---|
| 等待事件 | 轻微呼吸状态点 | “等待牌局更新” | 禁用 |
| 计算中 | 当前行动者高亮 | 骨架屏 + 已耗时 | 合法动作可用，避免模型阻塞玩家 |
| 建议就绪 | 稳定展示当前局面 | 主建议卡淡入 | 推荐动作描边 |
| 建议过期 | 新事件覆盖旧街 | 卡片降灰并标“已过期” | 以最新合法动作集为准 |
| 低置信度 | 无特殊警报 | 琥珀标签 + 两个候选动作 | 不默认强调单一动作 |
| 数据断流 | 顶栏连接转红 | 停止给出新建议 | 保留本地手动操作或进入复盘 |
| 一手结束 | 筹码归集、胜者轻高亮 | 展示结果与一句校准 | 显示“复盘本手” |

更新建议时不移动主按钮位置，避免倒计时内误触。涉及下注额的数字使用等宽数字，并统一显示 BB；悬停或展开后再显示筹码绝对值。

## 5. 视觉方向

- **关键词：** 克制、可信、竞技分析、低干扰、可审计；
- **主色：** Graphite `#111418`、Felt `#123B34`、Ivory `#F3EFE6`；
- **语义色：** Cyan `#39C6E8` 表示信息，Amber `#EAA73A` 表示不确定，Coral `#E85C55` 仅表示弃牌或风险；
- **字体：** 中文使用系统无衬线，数字和牌面使用等宽特征；正文不低于 14 px；
- **动效：** 150–220 ms，使用淡入和轮廓变化；兼容 `prefers-reduced-motion`；
- **可访问性：** 不仅依赖颜色表达动作；正文对比度至少 4.5:1；键盘焦点清晰；200% 缩放时建议轨下移为抽屉。

避免赌场金色、老虎机高光、赛博霓虹、无意义 3D 装饰和持续闪烁。

## 7. 与现有内核的接口映射

现有 `DecisionContext` 已能提供 hand、street、hole cards、board、pot、to-call、stack、legal actions 和 opponents；现有 `LLMPlayer` 结果可提供 action、raise scale、confidence、rationale、opponent model、risk flags 和 next step。

Web 层建议新增只读投影，而不是把 UI 绑定到 Python dataclass：

```json
{
  "snapshotId": "hand-284-street-flop-action-3",
  "capturedAt": "2026-08-01T12:00:00.032Z",
  "table": {
    "handIndex": 284,
    "street": "flop",
    "potBb": 7.6,
    "toCallBb": 1.5,
    "board": ["7h", "Jc", "2d"],
    "legalActions": ["fold", "check_call", "raise"]
  },
  "advice": {
    "action": "raise",
    "raiseToBb": 6.5,
    "confidence": 0.82,
    "equity": 0.64,
    "mix": {"fold": 0.18, "call": 0.27, "raise": 0.55},
    "summary": "权益领先且对手面对持续压力弃牌偏高",
    "risks": ["对手样本量较低"],
    "expiresOnSnapshotChange": true
  }
}
```

`mix` 不是当前 `LLMPlayer` 的既有输出。首版可以只显示单一建议和置信度；若要展示混合策略，应新增经过校准的策略模型或明确标注为启发式分布，不能把模型置信度伪装成 GTO 频率。

事件链建议为：`允许的数据源 → 标准化 HandEvent → TableSnapshot → Equity/Policy/LLM Advice → WebSocket → 只读 UI`。每条建议携带 `snapshotId`；任何新动作到达后立即使旧建议失效。

## 8. 响应式策略

- `≥ 1280 px`：牌桌 + 右侧建议轨；
- `900–1279 px`：建议轨压缩为 360 px，次要依据折叠；
- `< 900 px`：牌桌在上，建议为底部抽屉，不与第三方移动端牌局叠层；
- 触屏按钮最小 48 px，关键操作之间至少 12 px 间隔。

## 9. MVP 交付顺序

1. 用仓库仿真事件做只读六人桌和本手时间线；
2. 接入现有 `LLMPlayer` 的单一动作、尺度、置信度和简短依据；
3. 加入 WebSocket 新鲜度、过期保护、断流与低置信状态；
4. 做复盘模式、玩家选择记录和“建议 vs 实际”校准；
5. 仅在规则许可的数据源上增加实时牌局适配器。

## 10. 交付约束与下一步交接

- **产品/合规：** 明确每个数据源是否允许实时辅助；
- **后端：** 定义 `HandEvent`、`TableSnapshot`、`AdviceEnvelope` 和过期语义；
- **前端：** 实现桌面优先原型，并验证 6 人桌、窄屏、键盘、200% 缩放、断流和倒计时；
- **扑克/模型：** 校准 equity、置信度和任何策略混合，区分模拟证据与真实牌局表现；
- **视觉：** 基于本 brief 产出 Figma 组件、SVG 牌组和状态动效规范。
